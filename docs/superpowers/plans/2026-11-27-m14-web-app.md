# M14: Taskwise on the web — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The same Taskwise app running in a browser (Brutal + Lapis, light/dark), signing in to any Taskwise server as a `web` device, behind a public home page on Vercel. M15 adds web reminders.

**Architecture:** One Flutter code base. A small `AppTarget` helper replaces every `dart:io` `Platform.isX` call, so web runs never touch native-only code. Web-only code (`package:web`) sits behind conditional imports. The database is drift's web build (WASM sqlite, OPFS or IndexedDB). A static site (home page + `/app/`) is built in GitHub Actions and deployed to its own Vercel project when a release is published. The sync server gains CORS and the `web` device type.

**Tech Stack:** Flutter 3.47.7 web (JS + CanvasKit, Flutter's service worker off), drift 2.35.2 / drift_flutter 0.3.1 web, `package:web`, Hono `cors`, Vercel CLI (pinned), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-27-web-app-design.md` (§7.1–7.3, §7.5 and §9 are M14; §7.4 is M15).

## Global Constraints
- Web designs: **Brutal (default) and Lapis only**, each light/dark/system. Any other stored design shows Brutal on the web.
- The web device registers as `DeviceType.web` (new value, appended last). Older apps already map unknown types to `other`.
- Site deploys on `release: published` (plus `workflow_dispatch`), never on tag push.
- Address: `<project>.vercel.app` (first choice `taskwise-app`), kept in one place: the repo variable `WEB_APP_URL`, used by the workflow and the docs.
- Never put the maintainer's name, email or server address in code, docs, the Vercel project name or commits (commit as `Krkr8`, noreply).
- Logs never contain task titles, notes, places, tokens or passwords.
- Pin every new package/action/CLI version; check it's maintained (SPEC §0 rule 4).
- Existing native behaviour must not change. All existing tests stay green: `cd app && flutter test`, `cd shared && dart test`, `cd server && npm test`.
- The sync protocol stays compatible with 1.2.x devices.
- User-facing text in English and Arabic (`app/lib/l10n/app_en.arb`, `app_ar.arb`), in the app's existing tone.

## Review Focus
1. **An `http://` server typed on the https site:** the browser blocks it (mixed content). Sign-in must say "This server must use https:// to work in the browser", not show a generic network error. Test in Task 5.
2. **A server that hasn't been updated (no CORS):** the browser reports only a failed request. On the web, a failed `/health` check reads "Can't reach this server from the browser. If it's yours, update it to Taskwise 1.3.0 or later." Test in Task 5.
3. **A design stored as Classic or Slate** (e.g. from an imported backup) on the web: shows Brutal, and the picker shows Brutal selected. Test in Task 4.
4. **Browser storage unusable** (private mode, quota, OPFS and IndexedDB both refused): the app starts on an in-memory database with a persistent warning bar ("This browser isn't keeping your tasks. Sign in to sync them, or leave private browsing."), never a blank page. Test in Task 3.
5. **Two tabs open at once:** both work on the same data (drift's shared worker / OPFS locking), and neither corrupts the database. Checked in the Task 9 browser test by opening a second tab.
